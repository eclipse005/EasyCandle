# 时间周期重设计提案（产品向，不写代码）

> 对照现状：固定 1m/5m/15m/1h/4h/1d，导入时全量预计算进 IDB；`aggregateCandles` 已支持任意秒级；4h/1d 用纽约收盘（NY 17:00）对齐；无周/月、无自定义分钟 UI。

## 推荐默认收藏（主栏）

**1m · 3m · 5m · 15m · 30m · 1h · 4h · 1d · 1w**

完整下拉里再加 **6h、1M**（用户可自行加星进主栏）。

理由：与 TradingView / FX Replay 外汇常用盘一致——3m/30m 是盘感与日内主流档；6h 补 4h↔日线之间的波段空档；1w 看结构几乎刚需；1M 复盘用得少但成本极低，放完整列表即可，避免默认主栏过挤。不必推翻现有六档，做「扩展 + 分层」即可。

## 其它决策

- **存储**：1m 仍是唯一源。导入时预计算并写入 IDB：`5m/15m/30m/1h/4h/1d`（30m 几乎零成本）。`3m/6h/1w/1M` 首次切换时从 1m（或日线）即时聚合，结果写入 IDB/会话缓存，下次秒开。单品种约 37 万根 M1 时，现行六档约几十 MB；若全预计算多约 +25–30%，可接受，但混合策略更省且切换体验仍好。自定义周期永不预计算。
- **周/月对齐（与现有 NY-close 一致）**：4h/1d 继续按纽约 17:00。**周线**以纽约时区的周日 17:00 → 下周日 17:00 为一根（TradingView 外汇周覆盖 / NY 收盘边界）。**月线**按纽约日历月，在月界用同一套 NY 17:00 收盘切桶。不做「用户自选周起始」v1。
- **自定义间隔（如 11m）**：本轮 **不做**。以后若做：输入框分钟数 → 仅从 1m 现算 + 内存/IDB 缓存，不进导入预计算、不进默认收藏。
- **迁移**：旧数据集只有六档时，**打开即可后台从已有 1m 补算缺档并回写 meta**，无需强制重新导入；用户也可在数据管理里一键「重建周期」。
- **复杂度**：推荐方案整体 **M**（加 3m/30m/6h + UI/收藏约 S；周月桶 + 打开时补算约 M；若同版塞自定义则变 L，故自定义往后放）。
